Visão Geral do Sistema

O Sistema de Avaliação de Academia é uma aplicação web progressiva (PWA) desenvolvida para coletar, armazenar e analisar a satisfação dos alunos de uma academia. O sistema opera em dois contextos distintos: um totem de autoatendimento instalado na academia (interface pública) e um painel administrativo acessível apenas por gestores autenticados.

Objetivo Principal
Medir a satisfação dos alunos em tempo real e fornecer dados acionáveis para a gestão da academia
Público-Alvo
Alunos da academia (totem público) e gestores/administradores (painel privado)
Tipo de Sistema
Web App estático hospedado no Firebase Hosting + Firestore como banco de dados em tempo real
Modelo de Acesso
Interface pública (sem login) para o totem + área restrita (login obrigatório) para o dashboard

Casos de Uso
UC-01 Registrar Avaliação de Satisfação (Totem)
Ator Principal
Aluno / Frequentador
Pré-condição
Nenhuma. O totem está disponível publicamente sem autenticação.
Descrição
O aluno interage com o totem em 5 etapas sequenciais para registrar sua experiência na academia. Ao finalizar, os dados são persistidos no Firestore e o sistema retorna automaticamente ao estado inicial.
Fluxo Principal
  1. Etapa 1 — Nota Geral: O aluno seleciona uma das 4 opções de experiência: Péssimo 😡, Regular 😐, Bom 😊 ou Excelente 🤩. O sistema emite feedback sonoro ao clicar.
  2. Etapa 2 — Tags de Contexto: Com base na nota geral escolhida, o sistema exibe tags relevantes. Se nota negativa (Péssimo/Regular): "Equipamentos", "Limpeza", "Atendimento", "Lotação". Se positiva (Bom/Excelente): "Professores", "Estrutura", "Clima", "Aparelhagem". O aluno seleciona uma ou mais tags.
  3. Etapa 3 — Identificar Colaborador: O sistema lista os colaboradores cadastrados com nome, cargo e foto. O aluno seleciona quem o atendeu ou opta por "Ninguém".
  4. Etapa 4 — Avaliação Estrutural: O aluno atribui 1 a 5 estrelas para Limpeza e Equipamentos. Opcionalmente informa um telefone ou CPF para contato futuro.
  5. Envio: O sistema salva o feedback no Firestore com timestamp e exibe tela de confirmação.
  6. Reset automático: Após 3 segundos, o totem retorna ao Passo 1 para o próximo usuário.
Fluxo Alternativo
  • [A1] Na Etapa 3, o aluno pode clicar em "Ninguém" para avançar sem selecionar colaborador.
  • [A2] Na Etapa 4, o campo de contato é opcional; o aluno pode enviar sem preenchê-lo.
Pós-condição
Um documento é criado na coleção avaliacoes do Firestore com todos os dados do feedback.
Regras de Negócio
  • A Etapa 2 exige ao menos uma tag selecionada para habilitar o botão "Avançar".
  • A Etapa 4 exige notas de Limpeza e Equipamentos maiores que zero para habilitar "Enviar Feedback".
  • Ao registrar uma nota "Péssimo", o sistema consulta as últimas 2 avaliações. Se ambas também forem "Péssimo", um alerta crítico é disparado.
UC-02 Autenticar-se como Administrador
Ator Principal
Administrador
Pré-condição
O administrador possui conta criada no Firebase Authentication do projeto.
Fluxo Principal
  1. O administrador acessa /admin/login.
  2. Insere e-mail e senha nos campos do formulário.
  3. Clica em "Entrar".
  4. O sistema chama signInWithEmailAndPassword no Firebase Auth.
  5. Em caso de sucesso, o sistema redireciona para /admin (dashboard).
Fluxo de Exceção
  • [E1] Credenciais inválidas: exibe a mensagem "Credenciais inválidas. Tente novamente." abaixo do formulário.
Pós-condição
Sessão autenticada criada; o administrador tem acesso às rotas protegidas /admin e /admin/equipe.
UC-03 Visualizar Dashboard de Satisfação
Ator Principal
Administrador
Pré-condição
Administrador autenticado (UC-02).
Descrição
O painel central do sistema exibe indicadores-chave de desempenho calculados em tempo real sobre as últimas 100 avaliações registradas.
Funcionalidades Disponíveis
  • Índice de Satisfação (%): Percentual de avaliações "Bom" + "Excelente" sobre o total.
  • Área com Mais Reclamações: A tag com maior frequência de seleção em avaliações negativas.
  • Funcionário Destaque: O colaborador mais mencionado positivamente.
  • Lista de Feedbacks: Histórico cronológico das avaliações com nota geral, tags selecionadas, colaborador mencionado e data/hora.
  • Contato do Aluno: Se preenchido, exibe botão de acesso rápido ao WhatsApp (para números de telefone).
Atualização em Tempo Real
Os dados são sincronizados via onSnapshot do Firestore — novos feedbacks aparecem automaticamente sem recarregar a página.
Pós-condição
Nenhuma alteração de estado no banco de dados.
UC-04 Gerenciar Equipe de Colaboradores
Ator Principal
Administrador
Pré-condição
Administrador autenticado (UC-02). Acesso via /admin/equipe.
Fluxo — Adicionar Colaborador
  1. Preenche nome (máx. 40 caracteres) e cargo (máx. 40 caracteres).
  2. Opcionalmente, faz upload de uma foto (JPG/PNG, máx. 5 MB). A imagem é salva no Firebase Storage em /equipe/{imageId}.
  3. Clica em "Adicionar Colaborador".
  4. O sistema salva o documento na coleção colaboradores do Firestore.
  5. O colaborador aparece imediatamente na lista ao lado e também no Passo 3 do totem.
Fluxo — Remover Colaborador
  1. Na lista de colaboradores, o administrador clica no botão de exclusão do card correspondente.
  2. O sistema remove o documento do Firestore e a imagem associada do Storage (se existir).
  3. O colaborador desaparece imediatamente da lista e do totem.
Validações
  • Nome e cargo são campos obrigatórios.
  • Tamanho máximo da foto: 5 MB.
Pós-condição
Coleção colaboradores atualizada; alterações refletidas em tempo real no totem público.
UC-05 Contatar Aluno via WhatsApp
Ator Principal
Administrador
Pré-condição
Avaliação registrada com campo "contato" preenchido com número de telefone válido.
Fluxo
  1. No dashboard, o administrador localiza um feedback com número de contato.
  2. Clica no botão de WhatsApp exibido na linha do feedback.
  3. O sistema abre o WhatsApp Web com o número pré-preenchido em uma nova aba.
Fluxo Alternativo
[A1] Se o contato for um CPF (não-numérico detectado como CPF), o botão de WhatsApp não é exibido — apenas o texto do contato é mostrado.
Pós-condição
Nenhuma alteração de estado no sistema; comunicação ocorre externamente via WhatsApp.
UC-06 Encerrar Sessão Administrativa
Ator Principal
Administrador
Pré-condição
Administrador autenticado com sessão ativa.
Fluxo
  1. Clica no botão "Sair" no dashboard administrativo.
  2. O sistema chama signOut(auth) do Firebase Auth.
  3. A sessão é invalidada e o usuário é redirecionado para /admin/login.
Pós-condição
Sessão destruída; as rotas protegidas ficam inacessíveis sem novo login.
4
Fluxo do Usuário no Totem (Detalhado)
1
Etapa 1 — Nota Geral

"Como foi sua experiência hoje?" — Quatro botões com emoji e label (Péssimo / Regular / Bom / Excelente). Som de clique via Web Audio API. Avança automaticamente após seleção (delay 400ms).

2
Etapa 2 — Tags de Contexto

Tags dinâmicas conforme a nota. Negativas: Equipamentos, Limpeza, Atendimento, Lotação. Positivas: Professores, Estrutura, Clima, Aparelhagem. Multi-seleção permitida. Botão "Avançar" fica pulsante (verde) quando ao menos uma tag está selecionada.

3
Etapa 3 — Identificação do Colaborador

Lista horizontal com foto, nome e cargo dos colaboradores cadastrados (leitura ao vivo do Firestore). O aluno toca no cartão do colaborador ou na opção "Ninguém". Avanço manual com botão "Avançar".

4
Etapa 4 — Avaliação Estrutural

Dois grupos de estrelas (1–5): Limpeza e Equipamentos. Campo de texto opcional para telefone ou CPF. Botão "Enviar Feedback" habilitado somente com ambas as notas preenchidas.

5
Etapa 5 — Confirmação

Ícone de check animado + mensagem "Obrigado!". Reset automático após 3 segundos → Etapa 1.

// Gerado automaticamente ao concluir o totem

  cargo: string // Máx. 40 caracteres,

}

Observações e Pontos de Atenção
⚠️
Alerta de Avaliações Críticas Quando um aluno registra nota "Péssimo" e as 2 avaliações anteriores também são "Péssimo", o sistema registra um alerta crítico. Atualmente este alerta vai apenas para o console do navegador — não há notificação push ou e-mail para o gestor.
ℹ️
Biblioteca Recharts declarada mas não utilizada O pacote recharts está instalado como dependência, porém nenhum gráfico está renderizado nas páginas atuais. Isso indica planejamento de expansão futura para visualizações gráficas de tendências.
✅
Arquitetura adequada ao plano gratuito do Firebase O uso de output: 'export' no Next.js elimina a necessidade de Server-Side Rendering, mantendo o app totalmente compatível com o Firebase Spark (sem custo de Cloud Functions ou Container).
